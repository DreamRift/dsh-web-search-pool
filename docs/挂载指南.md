# 挂载指南：dsh-web-search-pool

> 本文说明如何把本项目的 `dsh-web-search-pool` provider 挂载进 DeepSeek Harness 并接管 `web_search`。
> 调研日期：2026-08-14（本会话）。机制结论均来自对已安装 DSH 源码的直接阅读，路径见文末「信息来源」。

## 1. 架构结论（为什么这样挂）

DSH 的网页搜索是**单一 provider** 架构：`web_search` 工具 → `ctx.web.search()` → 恰好一个 `WebSearchProvider`。
负载均衡必须封装在**单个 provider 内部**（本项目已这么做），但还有一个被忽略的坑：

- **host 层的 `web` row 已经显式配置了 `searchProvider: deepseek-official`**（见 `dsh-base/cordis.patch.yml`）。
  `WebRuntime` 里 `searchProviderId = config.searchProvider ?? env`（config 优先），所以光靠
  `$DSH_WEB_SEARCH_PROVIDER=search-pool` **不会生效**，必须覆盖 host 的 `web` row 配置。

因此 provider 挂到 **host 层**（profile 的 `cordis.patch.yml`），与内置 `web-search-deepseek` 对称放置，
同时覆盖 `web` 的 `searchProvider`。这样最干净，也天然规避了 seam 的 `WEB_PROVIDER_AMBIGUOUS`。

> 为什么不挂 preset（`agent.cordis.yml`）？provider 本身只消费 `web` 服务、不发布服务，技术上可以 loose 挂
> preset；但 `searchProvider` 的覆盖必须落在 host 层，既然都要动 host patch，provider 一起放 host 层更简洁。

## 2. 前置条件

- 已确定 `DSH_HOME`（例如 `C:\Users\<your-user>\.dsh`，按实际环境替换）。
- web profile 目录存在：`$DSH_HOME/profiles/web/`，内有 `cordis.patch.yml`、`package.json`、`pnpm-workspace.yaml`。
- 具备 `pnpm`（profile 的 `pnpm-workspace.yaml` 使用 `nodeLinker: hoisted`）。

## 3. 安装步骤

### 3.1 把 provider 包作为 out-of-tree 插件装进 profile

> **重要**：插件源码是 ESM，并且会通过 symlink 挂载。若直接 `file:` 指向源码目录，
> Node.js ESM 会沿 symlink 的**真实路径**查找 `node_modules`；源码目录没有 peer 依赖时，
> 会报 `Cannot find package '@deepseek-ai/dsh-settings'`。推荐先用 `npm pack` 生成 tgz。

#### 方式一（推荐）：引用打包后的 tgz

在插件仓库目录执行：

```bash
cd <本仓库绝对路径>
npm pack
```

然后在 `$DSH_HOME/profiles/web/package.json` 的 `dependencies` 加：

```json
{
  "dependencies": {
    "dsh-web-search-pool": "file:<本仓库绝对路径>/dsh-web-search-pool-0.2.0.tgz"
  }
}
```

#### 方式二：直接引用源码目录（必须先安装 peer 依赖）

```json
{
  "dependencies": {
    "dsh-web-search-pool": "file:<本仓库绝对路径>"
  }
}
```

在源码目录执行：

```bash
cd <本仓库绝对路径>
npm install --no-save \
  @deepseek-ai/cordis \
  @deepseek-ai/dsh-credentials \
  @deepseek-ai/dsh-launch-environment \
  @deepseek-ai/dsh-settings \
  @deepseek-ai/dsh-web \
  @deepseek-ai/schemastery
```

然后回到 profile 目录执行：

```bash
cd "$DSH_HOME/profiles/web"
pnpm install
```

> 将 `<本仓库绝对路径>` 替换为实际仓库路径；Windows 下路径含空格或中文时，若 `pnpm`
> 对 `file:` URL 编码报错，改用正斜杠绝对路径，例如 `file:C:/path/to/dsh-web-search-pool`。
> 使用方式二时，源码目录里的 `node_modules` 必须保留；删除后重启 DSH 会再次触发
> `ERR_MODULE_NOT_FOUND`。

### 3.2 编辑 `$DSH_HOME/profiles/web/cordis.patch.yml`

在数组里加两段（**保留已有的 `directory-picker` 覆盖**）：

```yaml
# ── 搜索 key 池：让 web_search 走 search-pool ────────────────────────────
# 覆盖 host 的 web row（patch 是「整段 config 替换」，所以重写完整 config）。
- id: web
  config:
    searchProvider: search-pool

# 新增 provider row（insert 追加到顶层条目列表）。
- insert:
    - id: web-search-pool
      name: 'dsh-web-search-pool'
      config:
        enabled: true              # 搜索开关：true=search-pool，false=DeepSeek 官方搜索
        providers:
          tavily:
            keys:
              - apiKeyEnv: TAVILY_API_KEY_1
                rpm: 60
                remark: 主账号        # 可选备注
              - apiKeyEnv: TAVILY_API_KEY_2
                rpm: 60
                remark: 备用账号
              # …… 共 10 个，按实际 plan 的 rpm 填写
            # 高级功能（均可省略，用默认值）：
            searchDepth: advanced      # basic | advanced，深度提取，默认 advanced
            includeAnswer: true        # 总结答案（answer → content），默认 true
            includeRawContent: false   # 原文内容，默认 false
            topic: auto                # general | news | finance | auto，默认 auto（按 query 判断）
            timeRange: auto            # day | week | month | year | auto | off，默认 auto（识别"今天/本周/…"）
            includeDomains: auto       # 域名列表 | auto | off，默认 auto（识别 site: 语法）
            excludeDomains: []         # 显式排除的域名列表
          exa:
            keys:
              # apiKeyEnv 留空 = Exa 官方托管 MCP 匿名免费层（无需 key，免费有限流）
              - apiKeyEnv: EXA_API_KEY_1
                rpm: 30
              # - apiKeyEnv: ""          # 匿名免费模式示例（可同时保留多个匿名 key 用于限流均衡）
            # 高级功能（均可省略，用默认值）：
            type: auto                 # auto | neural | keyword（Exa 语义，默认 auto）
            useAutoprompt: true        # 自动优化 query，默认 true
            highlights: true           # 深度提取-高亮，默认 true
            summary: true              # 深度提取-摘要，默认 true
            includeDomains: auto       # 域名列表 | auto | off，默认 auto
            excludeDomains: []         # 显式排除的域名列表
            startPublishedDate: auto   # YYYY-MM-DD | auto | off，默认 auto（按 query 时间词推导）
        strategy: weighted-round-robin   # 或 least-used
        providerPriority: [tavily, exa]
        allowedFails: 3
        cooldownMs: 30000
        retryAfterFallbackMs: 1000
        usageCacheMs: 300000              # Tavily 额度刷新间隔（毫秒），默认 5 分钟
        quotaReserveCredits: 2            # 保留下次使用额度；Tavily advanced 搜索为 2 credits
        quotaExhaustedCooldownMs: 2592000000   # 额度耗尽长冷却（毫秒），默认 30 天
```

> `providerPriority` / `strategy` / `allowedFails` / `cooldownMs` / `retryAfterFallbackMs` 均可省略（有 schema 默认值）。
> `enabled` 默认 `true`；每个 key 可加可选 `id`（缺省为 `<provider>:<apiKeyEnv>`）与 `remark`（备注）；
> `rpm` 缺省 60，**应按各 key 的实际 plan 限流值填写**。
>
> **额度控制**：Host 定期查询 Tavily `/usage`，设置页显示所有 Tavily key 的总已用/总上限/总可用；
> 某 key 剩余额度低于 `quotaReserveCredits` 时自动进入 `quotaExhaustedCooldownMs` 长冷却，
> 额度恢复并刷新后自动解除。Exa 无公开余额接口，不计入总额。
> 设置页的「立即刷新」按钮通过 `usageRefreshTick` 计数触发 Host 重新查询 `/usage` 并更新 UI。
> `usageRefreshTick`、`usageDiagnostic`、`usage` 是运行时字段，由 Host/Client 自动维护，**不需要手动配置**：
> - `usageRefreshTick`：手动刷新计数，点击「立即刷新」时递增；
> - `usage`：最近一次额度快照（`updatedAt`/`totalUsed`/`totalLimit`/`keys[]`）；
> - `usageDiagnostic`：额度刷新/发布失败时的诊断信息（会列出失败 key 或超时），为空表示上次刷新全部成功。
> 手动刷新有 15 秒总超时；即使 Tavily API 挂起，Host 也会写回诊断，避免点击后静默无反馈。
>
> 设置页卡片默认收起；已保存/匿名的 key 也默认折叠为一行摘要（名称、额度、状态），点开才显示完整编辑区。
> 编辑区底部按钮为「取消 / 保存」；点击「取消」丢弃草稿并收起卡片，点击「保存」成功后也自动收起，
> 与 harness 其他设置卡片一致。
>
> **Exa 可完全不填 key**：`apiKeyEnv` 留空，或填写了环境变量名但凭据未配置时，自动走 Exa 官方托管 MCP
> 的匿名免费层（`https://mcp.exa.ai/mcp` 的 `web_search_exa`，无需注册、免费有限流）。
> 匿名免费层为**共享配额**：无论配置多少个匿名 Exa key，全局强制 **1 秒 1 次**，该限制不可被配置覆盖。
> 填写 `EXA_API_KEY` 后走 REST（`api.exa.ai/search`），支持全部高级参数且配额更高，不受匿名限流影响。

**高级功能三态语义**（Tavily 的 `answer`/`search_depth`、Exa 的 `useAutoprompt`/深度提取默认**打开**）：

- `auto`（默认）：AI 可选——provider 按 query 语义自动决定。识别信号：时间词（今天/本周/最近N天/this week…）、
  `site:example.com` 或 `https://…` 域名、新闻/财经主题词。
- 具体值：显式写死（如 `timeRange: week`、`includeDomains: [a.com]`）。
- `off`：禁用该项（不发送对应参数）。

> Tavily 的 `searchDepth: advanced` + `includeAnswer: true` 是文档推荐的「一次搜索替代 search+fetch」组合；
> 注意这种 advanced 搜索按 Tavily 计费为 2 credits（免费额度 1000 → 约 500 次）。

### 3.3 配置凭据

key 的明文不进配置。凭据解析顺序（`dsh-credentials-local`）：进程环境变量 > `$DSH_HOME/.credentials.yaml` > `.env` 回退。
二选一：

- 环境变量（进程启动时注入）：`TAVILY_API_KEY_1=… TAVILY_API_KEY_2=… EXA_API_KEY_1=… dsh …`
- 或写入 `$DSH_HOME/.credentials.yaml`：

```yaml
TAVILY_API_KEY_1: tvly-<your-tavily-key>
TAVILY_API_KEY_2: tvly-<your-tavily-key>
EXA_API_KEY_1: exa-<your-exa-key>
```

### 3.4 暴露 `web-search-pool` 到设置页（必须，DSH 安装目录 patch）

官方结论（已核对 DSH 0.1.0-rc.6 源码与 `dsh-host-apiproxy/README`）：`settings.describe`/`settings.update`
只服务**白名单内**的 namespace；插件仅注册 Settings **不会**自动暴露（源码注释明确这是「deferred work」）。
要让设置页的「搜索 Key 池」卡片能读/写配置，必须把 `"web-search-pool"` 加进 `api-proxy` 的
`WEB_SETTINGS_NAMESPACES`。该文件位于 npm 安装目录，**DSH 升级会覆盖**。

**推荐方式：运行自动化脚本**（幂等，可重复执行；跨平台 Windows / macOS / Linux）：

```bash
node "<项目目录>/scripts/patch-api-proxy-namespace.mjs"
```

脚本会：
1. 按序定位 `dsh-host-apiproxy/lib/index.js`：`DSH_API_PROXY_INDEX` 显式指定 → Windows
   `%APPDATA%\npm\node_modules` → 从当前 node 可执行文件推导的全局 `node_modules`（覆盖
   nvm / homebrew / 系统安装）→ `/opt/homebrew/lib/node_modules` → `/usr/local/lib/node_modules`；
2. 若白名单已含 `"web-search-pool"` 则跳过；
3. 否则在 `"web-search-deepseek"` 锚点行后追加（自适应锚点行的缩进 Tab/空格与换行 CRLF/LF），
   写入前先用 `node --check` 做语法校验（校验失败不写入），并保留 `.bak` 备份。

均未命中时，按脚本输出的提示设置 `DSH_API_PROXY_INDEX` 指向目标文件完整路径后重跑，例如：

```bash
# macOS / Linux（按实际安装位置调整）
export DSH_API_PROXY_INDEX=/usr/local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-host-apiproxy/lib/index.js
# Windows（PowerShell）
$env:DSH_API_PROXY_INDEX = "C:\Users\<you>\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-host-apiproxy\lib\index.js"
```

等价的手工改动：

```js
const WEB_SETTINGS_NAMESPACES = [
  "agent-loop",
  "shell",
  "locale",
  "permission",
  "ui-conversation",
  "ui-theme",
  "web-search-deepseek",
  "web-search-pool"   // ← 追加
];
```

> ⚠️ 依赖该 patch 的 UI 能力：设置页卡片读配置、「编辑」写回、搜索开关切换。
> 若升级 DSH 后卡片又显示「provider 未挂载」，先运行上面的脚本，再重启 DSH。

### 3.5 历史会话兼容（背景说明，非安装步骤）

旧版插件曾向会话日志写入 `web/search-pool-attempt` 自定义事件，导致部分会话历史无法加载。已在另一处修复：
对历史日志事件补 `ignorable: true`，并把该事件类型补入 DSH 会话事件目录（`dsh-session`）。当前插件已停止写入
该事件（改用 `ctx.logger`）。若 DSH 升级覆盖 `dsh-session` 目录，历史日志仍因 `ignorable` 标记可正常加载，
无需重新 patch；新会话不再产生该事件。

## 4. 验证

1. 重启 dsh web（profile patch 在启动时加载；注意是**重启 DSH 进程**，不是只刷新浏览器）。
2. 设置页 → 插件 → 插件配置：出现「搜索 Key 池」卡片，默认收起；点击展开后显示真实配置。
   顶部开关可切换 search-pool / DeepSeek 官方搜索；每个已保存 key 默认折叠为摘要（名称/额度/状态），
   点击可展开编辑备注、环境变量名、限速与密钥。
3. 打开卡片后应看到「Tavily 额度总览」：已用 / 可用 / 上限 / 更新时间。点「立即刷新」会显示“刷新中…”和
   “已请求刷新，等待 Host 回写”；若 mutate 失败会显示“刷新请求失败”，若 Tavily 查询/发布失败，总览下方会显示
   「诊断：…」并列出失败 key 或超时。
4. 开一个真实 session，让模型调用一次 `web_search`；或直接观察启动日志里 `web-search-pool` 插件被 apply。
5. 确认多 key 轮换：`search-pool` 会把每次尝试写入插件日志，
   可据此核对是否按 rpm 权重分布、429 时是否自动换 key。

> 想确认 provider 是否真的被选中：把 `web` 的 `searchProvider` 临时改回 `deepseek-official` 对比行为即可。
> 若日志出现 `WEB_PROVIDER_CONFIGURED_MISSING`，说明 `dsh-web-search-pool` 包没被 loader 解析（回到 3.1 检查 pnpm 链接）。

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Cannot find package 'dsh-web-search-pool'` | 包没进 `profiles/web/node_modules`；重跑 `pnpm install`，或检查 `file:` 路径。 |
| peer 依赖找不到 | flat fallback 未就绪；重跑一次 dsh 启动（它会 `healProfilesModuleFallback`），或手动 `pnpm install` 补齐。 |
| 仍然走 deepseek 搜索 | `web` 的 `searchProvider` 覆盖没生效；确认 patch 里 `id: web` 段存在且 YAML 结构正确。 |
| 某 key 一直不被选中 | 该 key 可能处于冷却（429 熔断）或令牌耗尽；查 `search-pool attempt` 插件日志。 |
| 点击「立即刷新」时间不变 | 已改为 `settings/updated` 事件兜底触发 Host 刷新，但仍需先确认已**重启 DSH 进程**（不是只刷新页面）；若页面显示“刷新请求失败”则看浏览器/连接错误；若显示诊断则按诊断处理（未配置凭据 / Tavily 失败 / 超时）；若重启后仍无错误提示也无诊断，请把插件日志和 `usageRefreshTick`/`usage.updatedAt` 反馈给维护者。 |
